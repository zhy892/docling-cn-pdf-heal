# 国奖标准差距清单

## 已完成

- 可运行的 PDF 体检与选择性 OCR CLI；
- 自生成中文故障集、开发/测试/保留集划分；
- 三类页面：正常文本、错误 ToUnicode、纯图像扫描；
- 冻结测试的检测 Precision、Recall、F1 与 CER；
- 全页 OCR、原生文本层、选择性 OCR 三基线；
- 许可证工作清单与不公开第三方 PDF 的边界；
- 上游 Issue 设计留言草稿。

## 必须补齐，才可主张国奖竞争力

1. 至少一类真实、可合法本地测试的乱码 PDF，并在报告中区分“合成”和“真实”结果；
2. 至少一种非空白型乱码，如 `/gid...`、CID 逸码或看似汉字的错误映射；对 OCR 与文本层冲突页给出人工复核记录，而不只报告自动路由；
3. 更大规模、可重复的测试集与至少 3 次独立计时；
4. 阈值只在开发集选择，保留集不参与调参；
5. 至少 2 位目标用户试用及原始反馈记录；
6. 自有公开仓库、可安装 README、版本标签、无密钥扫描；
7. 至少一个已发布的上游 Issue 评论或 PR，附维护者反馈状态；
8. 15 页内技术报告、3–5 分钟视频、答辩问答包和匿名化审查。

## 禁止的表述

- 不把“检测乱码并回退 OCR”写成团队首创；应明确 #2963、#3081、#3582 是问题来源；
- 不把合成集 F1=1.0 写成“真实场景达到 100%”；
- 不把单机、单次、8 页耗时写成普遍提速结论；
- 不把未合并 PR 写成“已被 Docling 采用”；
- 不把 AI 协助的代码或文字写成未经审核的自主开发。
