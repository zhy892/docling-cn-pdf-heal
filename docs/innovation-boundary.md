# 创新边界与上游归因

## 一句话定位

本项目不是提出 OCR，也不主张首次提出“乱码后回退 OCR”。它为中文 PDF 入库提供**可解释的页级质量路由与可复现评测体系**：在保留正常文本层的前提下，给出每页“保留、建议 OCR、需要人工复核”的证据。

## 已有工作与归因

- Docling Issue [#2963](https://github.com/docling-project/docling/issues/2963) 已公开提出“检测损坏文本层并回退 OCR”的需求和整份强制 OCR 的现有绕行方案；
- Issue [#3081](https://github.com/docling-project/docling/issues/3081) 已报告缺少 `/ToUnicode` 时输出 `/gid...`；
- Issue [#3582](https://github.com/docling-project/docling/issues/3582) 已报告中文国标封面出现表面像汉字的错误映射，且强制全页 OCR 未必恢复。

这些 Issue 是问题来源和对比依据，不是团队的原创发现。团队不复制其中的代码、附件或表述，也不宣称已解决上述上游全部问题。

## 团队自主贡献

1. **页级可解释路由**：将显式字形/CID 伪码、替换字符、私有区字符、控制字符和空提取转化为具名质量证据；正常页保留文本层，异常页才建议 OCR。
2. **非空白乱码审计**：对已有 OCR 转写和文本层做规范化一致性比较，输出 `agreement_acceptable`、`ocr_text_disagreement` 或 `insufficient_text`，不把 OCR 自动当作真值。
3. **可复现中文故障注入**：从团队自撰文本构造正常、错误 ToUnicode 与纯图像三类输入；开发/测试/保留集分离，公开生成脚本而非受版权保护的真实 PDF。
4. **可核验评测协议**：同时报告检测混淆矩阵、CER、按故障类型的路由率、OCR 页数、重复计时原始值与中位数，并如实记录未复现样本。
5. **上游最小变更设计**：将能力拆为默认关闭的质量报告、维护者确认后的元数据接入、再到逐页 OCR 调度三步；第一 PR 不改变 Docling 转换结果。详见[具体合入设计](docling-integration-plan.md)。

## 不主张的内容

- 不主张 OCR、PDF `/ToUnicode` 修复、字形 ID 检测或“自动回退”本身由团队首创；
- 不主张所有乱码都能被检测或修复；
- 不将合成集结果外推为真实文档效果；
- 不将未合并的上游 PR 写成 Docling 已采用。

## 答辩可验证主线

输入 PDF → 文本层质量证据 → 页级路由/不确定状态 → 已有 OCR 的局部调用或转写交叉审计 → 结构化审计报告 → 冻结评测与失败案例。

评委可在不访问任何受限 PDF 的情况下复跑自制基准、检查全部路由理由，并验证系统不会把正常页一概改为 OCR。
