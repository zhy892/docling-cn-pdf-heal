# 评测协议 v0.2

## 目标

在固定测试集上比较默认文本层、强制全页 OCR 与自适应页级 OCR 回退的质量和耗时。

## 数据划分

- 合成损坏集：由团队可公开文本和可再分发字体生成；
- 合成正常集：同源未损坏页面；
- 真实集：仅本地评测，仓库仅保存页级元数据与人工标注，不再分发原始 PDF。

## 首个可公开故障样本

`benchmark/generate_synthetic_pdf.py --font <local-NotoSansSC.ttf>` 用团队自撰文本生成 `clean_chinese.pdf`，再安装将汉字错误映射到私有区的 `/ToUnicode` CMap，得到 `corrupt_tounicode_chinese.pdf`。字体仅在本地下载和使用，仓库不再分发；脚本、团队自撰文本和生成文件可公开。它不包含第三方标准、教材或论文。缺失 `/ToUnicode` 的真实样本将单独作为本地评测样本，不替代该可复现基准。

## 主要指标

- 损坏页检测 Precision、Recall、F1；
- 文本规范化后的字符错误率（CER）；
- 干净页误报率；
- 文档总耗时和 OCR 页数占比；计时报告 3 次后热运行的中位数及每次原始值；
- 按 `clean`、`corrupt_tounicode`、`scanned_image` 三类分别报告 OCR 路由率，避免总体 F1 掩盖某一类失败。
- 对“空提取”候选单列报告视觉空白页跳过率、渲染失败次数和失败开放策略，避免把真正空白页误计为 OCR 成本或检测成功。

小型合成集的计时须分别报告“文本层解析与路由时间”“被选页面 OCR 时间”和“总时间”；每轮完整方法顺序轮换一次，以降低缓存/热状态的系统偏差。不得把冷启动时间或小型合成集的结果表述为一般性性能结论。

## 冻结规则

阈值只可在开发集确定。最终测试集、Docling 版本、OCR 模型版本、硬件信息和随机种子一经记录不得调整；最终表由单一脚本生成。

阈值不是主观固定的 `0.20`：`threshold_calibration.calibrate_threshold` 只读取开发集质量分和 `is_damaged` 标签，在全部已观测分数及 0 中枚举候选值，依次以最高 F1、最低干净页误报率、最高阈值（最少侵入）决胜。应在读取冻结测试标签前把阈值、候选数量、开发集混淆矩阵和误报率写入证据日志；测试集和保留集只使用该已冻结值。默认 `0.20` 仅是未校准 CLI 的保守运行默认值，不能作为比赛结论中的“最优阈值”。

可用 `benchmark/calibrate_quality_threshold.py <all-pages.json> <manifest.json> --output calibration.json` 固化该选择。脚本逐页核对 manifest 的页码，且只读取 `split=development` 的标签；页码错位、缺少开发标签或试图将测试集替代开发集都会报错。`calibration.json` 是比赛材料中应保留的证据文件。

`all-pages.json` 必须由同一固定文本层后端从全体合成页面导出，而非人工复制或从真值生成。使用 `benchmark/extract_text_layer_pages.py <all.pdf> --backend native-docling --output all-pages.json`；输出仅含后端名和按页文本，标签仍独立保存在 manifest 中。这样可使阈值校准的输入、后端和标签边界均可复查。

运行冻结测试时，必须向 `run_synthetic_benchmark.py` 传入 `--calibration calibration.json`。输出会回显 `routing_threshold` 与证据文件名；缺省阈值的运行只能作为开发/演示，不能写入冻结测试结论。

## 合成集 v1

`benchmark/generate_dataset_v1.py` 生成 20 页：每四页包含 2 页正常文本层、1 页错误 ToUnicode 映射、1 页纯图像扫描页。页 1–8 为开发集，9–16 为冻结测试集，17–20 为保留集。测试集同时包含三类输入，不能在运行测试后调整阈值或规则。

## 合成集 v2

v1 的生成规则和已记录结果保持冻结。`benchmark/generate_dataset_v2.py` 独立生成 24 页，并新增真正空白页：每六页包含 3 页正常文本、1 页错误 ToUnicode、1 页扫描图像和 1 页空白。页 1–8 为开发集，9–18 为冻结测试集，19–24 为保留集。空白页标注为 `is_damaged=false`；最终检测指标按视觉空白守卫后的实际 OCR 页计算，而不是按规则层初始候选计算。

## 真实样本审计规则

公开 Issue 附件和公开可访问文档只能作为本地验证对象：不得加入仓库、发布压缩包、训练集或比赛附件。对每份样本记录来源链接、访问日期、软件版本、页数、是否复现和失败原因；未复现同样必须记录。真实样本没有可公开逐字真值时，不报告 CER、准确率或“修复率”，只报告可审计的触发页数和人工抽查结论。

对本地真实样本可使用 `--audit-id` 生成可公开的最小审计记录：团队编号、SHA-256、处理后端、页数、OCR 初始候选页和视觉空白跳过页。该记录不含原文件路径、文件名或文本内容；来源链接与访问权限说明另存于受控证据表，不能用哈希代替数据授权证明。

## 非空白、表面可读乱码的复核

规则层无法可靠识别所有“仍落在汉字 Unicode 区间、但字形映射错误”的文本。因此提供可选 OCR 交叉校验：对已取得的页级 OCR 转写与文本层做与 CER 相同的 NFKC/空白规范化比较。双方各至少 12 个规范化字符且一致率低于 0.65 时，输出 `ocr_text_disagreement` 和 `manual_review`；短页输出 `insufficient_text` / `insufficient_evidence`，不作路由结论；一致页输出 `keep_text_layer`。该模块是可审计的异常提示，OCR 不是自动真值，人工抽查仍是最终判断。

## 空白页误报控制

当文本层为空时，系统不会直接假定页面是乱码：先以 72 DPI 渲染灰度 PGM，统计深色像素数量与覆盖率。仅被判为视觉空白的候选页跳过 OCR，并在报告中记录 `skipped_blank_pages` 与 `ink_estimates`。渲染失败不是空白证据，候选页必须继续进入 OCR（失败开放），以避免将工具故障伪装成“正常空白页”。视觉空白阈值是工程筛选条件，须在开发集固定，并在保留集报告误跳过情况。
